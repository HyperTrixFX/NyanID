# 用户管理与工单系统

本文档描述 V3 管理端的**用户管理**与**工单（Ticket）**功能，以及 V1 的工单自助端点。

- 用户管理端点：`/api/zako/v3/users`（鉴权节点 `nyanid.admin.user`）
- 工单管理端点：`/api/zako/v3/tickets`（鉴权节点 `nyanid.admin.ticket`）
- 工单自助端点：`/api/zako/v1/ticket`（仅需登录态）

## 1. 分层结构

沿用 `ProxyController` → `ProxyFuncImpl` 的既有范式，Controller 只做「鉴权 + 转发」，业务逻辑全部在 Services 层：

```
server/V3Contorller/UserManagerController.java   # 用户管理端点
server/V3Contorller/TicketController.java        # 工单管理端点
server/V1Controller/UserTicketController.java    # 工单自助端点
services/impl/UserManageFuncImpl.java            # 用户管理业务
services/impl/TicketFuncImpl.java                # 工单业务（V1/V3 共用）
repository/UserTicketRepository.java             # 工单仓储
dto/UserEditDTO.java / TicketCreateDTO.java / TicketHandleDTO.java
```

## 2. 权限节点

新增两个细粒度节点（见 `utils/System/PermissionNodes`）：

| 节点 | 含义 |
| --- | --- |
| `nyanid.admin.user` | 用户管理（列表/详情/编辑/启停/封禁/解封/权限） |
| `nyanid.admin.ticket` | 工单管理（查看/处理工单） |

根节点 `*` 自动拥有以上全部权限；二者独立授予，互不影响。

## 3. 用户管理（V3，`/api/zako/v3/users`）

鉴权：`Authorization: Bearer <加密 token>` + `Event` 头（`/api/zako/v3/**` 已挂 `AuthenticateCheck`），服务端解析出 uid 后校验 `nyanid.admin.user` 节点；无权限返回 `403 Permission denied!`。

| 方法 | 路径 | 参数 / 请求体 | 说明 |
| --- | --- | --- | --- |
| GET | `/api/zako/v3/users` | query `keyword`（可选）、`page`、`size` | 分页列出 / 搜索用户 |
| GET | `/api/zako/v3/users/banned` | query `page`、`size` | 分页列出当前生效封禁的用户（含封禁详情） |
| GET | `/api/zako/v3/users/developers` | query `page`、`size` | 分页列出开发者用户 |
| GET | `/api/zako/v3/users/{uid}` | path `uid` | 用户详情（账号 + 资料 + Yggdrasil + 权限 + 封禁/设备统计） |
| PUT | `/api/zako/v3/users/{uid}` | `UserEditDTO` | 编辑资料（只更新非空字段） |
| PUT | `/api/zako/v3/users/{uid}/active` | query `active`（boolean） | 账号启停 |
| PUT | `/api/zako/v3/users/{uid}/developer` | query `active`（boolean） | 设置 / 取消开发者标志 |
| POST | `/api/zako/v3/users/{uid}/ban` | query `reason`、`type`、`expire`（均可选） | 封禁账号 |
| DELETE | `/api/zako/v3/users/{uid}/ban` | - | 解封该账号全部生效封禁 |
| GET | `/api/zako/v3/users/{uid}/permissions` | - | 查询权限节点集合 |
| POST | `/api/zako/v3/users/{uid}/permissions` | query `node` | 授予权限节点 |
| DELETE | `/api/zako/v3/users/{uid}/permissions` | query `node` | 回收权限节点 |

**UserEditDTO**

```json
{ "nickname": "...", "description": "...", "exp": 100, "isDeveloper": false }
```

- 四个字段均可选，只更新传入的非空字段；传 `null` 的字段不修改。

**封禁（POST `/ban`）**

- `reason`：原因，缺省 `"Banned by an administrator"`。
- `type`：封禁类型，缺省 `6`（死封，`BanUserList.TYPE_DEAD_BAN`）；可用任意 `BanUserList.Type` 覆盖。
- `expire`：解封时间，ISO-8601 格式（如 `2025-01-01T00:00:00`）；缺省/空 = 永久。
- 操作者自动取自当前 token 解析出的 uid（写入 `BannedBy`）。
- 成功返回 `{ "message": "Banned", "banId": "...", "timestamp": ... }`。

**解封（DELETE `/ban`）**

- 调用 `BanUserRepository.deactivateByUid`，把该 uid 下所有 `isActive=true` 的封禁置为失效。

### 安全说明

用户列表与详情**只返回安全字段**（uid、username、email、isActive、registerTime、profile、bind、yggdrasil、permissions、统计），**绝不返回** `password`、`SecretKey`、`MicrosoftAccount`、`GithubAccessToken` 或设备 `Token`。

## 4. 工单系统

### 4.1 实体 `UserTicket`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `TicketId` | String（主键，13 位随机） | 工单编号 |
| `type` | int | 工单类型（见下方常量） |
| `Description` | String（varchar 155） | 工单内容 |
| `userid` | String（varchar 32） | 提交人 NyanID UID |
| `status` | `TicketStatus`（枚举字符串） | 状态 |
| `createdAt` / `updatedAt` | LocalDateTime | 创建/更新时间（自动） |
| `handlerUid` | String（可空） | 处理人 UID，未指派为 `null` |
| `reply` | String（可空，varchar 512） | 管理员回复，未回复为 `null` |

**工单类型常量**

| 常量 | 值 | 含义 |
| --- | --- | --- |
| `TYPE_BAN_APPEAL` | 1 | 禁封申诉 |
| `TYPE_DEV_APPLY` | 2 | 开发者申请 |
| `TYPE_ACCOUNT_SECURITY` | 3 | 账号安全申诉 |

### 4.2 状态机 `TicketStatus`

| 枚举 | code | 含义 |
| --- | --- | --- |
| `PENDING` | 0 | 待处理（新建默认） |
| `PROCESSING` | 1 | 处理中 |
| `APPROVED` | 2 | 已通过 |
| `REJECTED` | -1 | 已拒绝 |
| `CLOSED` | 3 | 已关闭 |

### 4.3 用户自助（V1，`/api/zako/v1/ticket`）

只需 `Authorization: Bearer <加密 token>` 解析出 uid，不校验管理权限节点：

| 方法 | 路径 | 请求体 | 说明 |
| --- | --- | --- | --- |
| POST | `/api/zako/v1/ticket` | `TicketCreateDTO` | 提交工单 |
| GET | `/api/zako/v1/ticket` | - | 我的全部工单 |
| GET | `/api/zako/v1/ticket/{ticketId}` | - | 我的某一单（校验归属） |

**TicketCreateDTO**

```json
{ "type": 1, "description": "申诉内容" }
```

- `type` 仅接受 1/2/3；`description` 必填且 ≤ 155 字符。

**提交规则（`TicketFuncImpl.createTicket` 校验）**

| 类型 | 规则 |
| --- | --- |
| 1 禁封申诉 | ① 账户必须存在**活跃异常**（有生效中的封禁）；② 已有未结束的禁封申诉工单时禁止再次发起 |
| 2 开发者申请 | ① 用户已是开发者（`IsDeveloper=true`）则禁止；② 已有未结束的开发者申请工单时禁止再次发起 |
| 3 账号安全申诉 | 已有未结束的账号安全申诉工单时禁止再次发起 |

- 「未结束」= 工单状态为 `PENDING` / `PROCESSING`（即 `TicketStatus.isFinished() == false`）。
- 三类工单都按「同类型」查重（`UserTicketRepository.findByUseridAndType` + `TicketStatus.isFinished()`）。
- 命中规则时返回：`403 账户不存在活跃异常，无法申请禁封申诉`；`409 您已是开发者，无需重复申请`；`409 已有未结束的（禁封申诉/开发者申请/账号安全申诉）工单，请等待处理完成`。

> 「活跃异常」= 该 uid 存在 `isActive=true` 的封禁记录；该状态下账号可登录但只读（禁止资料/2FA/密码修改），见 [08-权限与封禁系统](./08-权限与封禁系统.md)。

> **设计说明**：V1 工单端点**刻意不挂 `AuthenticateCheck` 拦截器**。因为该拦截器会拦截被封禁账号（`LEVE450TRUE` → 401），而 `type=1` 正是「禁封申诉」，被封用户必须能提交申诉。故这里只在 Controller 内做 token→uid 校验，token 无效返回 `401 Unauthorized`。

### 4.4 工单管理（V3，`/api/zako/v3/tickets`）

鉴权节点 `nyanid.admin.ticket`：

| 方法 | 路径 | 参数 / 请求体 | 说明 |
| --- | --- | --- | --- |
| GET | `/api/zako/v3/tickets` | query `status`（可选）、`page`、`size` | 分页列出工单，可按状态过滤 |
| GET | `/api/zako/v3/tickets/{ticketId}` | path | 查看一单 |
| PUT | `/api/zako/v3/tickets/{ticketId}` | `TicketHandleDTO` | 处理工单（更新状态 / 指派处理人 / 回复），`PENDING` / `PROCESSING` 可处理 |

**TicketHandleDTO**

```json
{ "status": "APPROVED", "handlerUid": "<管理员uid>", "reply": "审核通过" }
```

- `status`：`PENDING` / `PROCESSING` / `APPROVED` / `REJECTED` / `CLOSED`（非法值返回 400）。
- `handlerUid`：可选，传入则覆盖处理人；不传保持原值。
- `reply`：可选，管理员回复（≤ 512 字符）。
- **锁定规则**：`PENDING` / `PROCESSING` 可处理（可再次修改）；一旦变为终态（`APPROVED` / `REJECTED` / `CLOSED`）即锁死，再次处理返回 `409 工单已处理，无法再次修改`。

## 5. 数据库迁移注意

`UserTicket` 的 `handler_uid` 从「NOT NULL」改成了「可空」。`ddl-auto=update` 只会**新增**列/表，**不会**自动放宽已有列的 NOT NULL 约束。

- 若 `user_ticket` 表是本次新功能首次生成（此前无 `UserTicketRepository`，大概率未建表），无需处理。
- 若表已存在，需手动执行一次：

```sql
ALTER TABLE user_ticket MODIFY handler_uid varchar(32) NULL;
```

> 新增的 `reply` 列（可空）会由 `ddl-auto=update` 自动 `ADD COLUMN`，无需手动处理。
