# 常见问题与故障排查

## 代理 / 协议

### 1.21.1 `/server` 补全崩溃（cookie_request … 20 bytes extra）

补全响应的包 ID 用错了：把 play 阶段的 `cookie_request` ID 当成了 `command_suggestions`。应使用 `command_suggestions` 的 ID（见 `UpstreamBridge.buildTabCompleteResponse`）。

### 切换服务器卡在「reconfiguring」然后后端超时

1.20.2+ 切换后读取没有恢复。确保：
- `ServerConnector.onLoginSuccess` 的切换分支恢复 `setAutoRead(true)`；
- 切换期间丢弃客户端残留的 GAME 帧（`switchingServer` + `UpstreamBridge` 丢弃逻辑）。

### 切换后 TabList 不刷新 / header/footer 丢失 / 皮肤层披风丢失

- TabList：名字追踪要独立于装饰开关；切换后重新推送 header/footer。
- 皮肤层/披风：`ClientSettings`（含 `skinParts`）要在配置阶段捕获并在切换后重放。

### 后端命令无法 Tab 补全（1.20.1 / 1.21.1）

代理用合成命令树替换了后端 `declare_commands`。若后端命令名提取失败，通常是 `DownstreamBridge.skipParserProperties` 的属性字节宽度写错导致遍历漂移：
- `float`/`integer` 边界 = 4 字节；
- `double`/`long` 边界 = 8 字节；
- `time` = 4 字节 int；
- `string` = VarInt。

### 同一条 ConnectOther 执行了两次（多玩家在线）

后端会通过每个在线玩家的连接重复下发同一条 `Connect`/`ConnectOther`。已修复：
- `PluginMessageService.claimConnect` 对 `(目标, 服务器)` 做 1 秒去重；
- `PlayerTransferService.transfer` 用 `synchronized(user)` + `switchingServer` 保证幂等。

## 数据库

### `Field 'xxx' doesn't have a default value`

`ddl-auto=update` 只加列、不删列。实体主键/列重命名后，旧 NOT NULL 列仍在表里却没被映射，插入就报错。解决：
- 手动 `DROP TABLE` 让 Hibernate 重建，或手工 `ALTER TABLE ... DROP COLUMN ...`。

## 防火墙 / 机器人

### 被机器人冲爆（Mojang session returned no profile + 大量断连）

启用 `proxy.firewall`，限制每 IP 连接速率 / 并发 / 登录尝试次数，超限临时封禁 IP。玩家成功进入后端后该 IP 计数重置。

## 权限

### 指令提示「你没有权限使用这个指令」

该命令注册了权限节点。给玩家授予对应节点（或 `*`）：

- 授予 root：`/op <uid>`
- 授予具体命令节点：`POST /api/zako/v3/proxy/permissions?uid=<uid>&node=minecraftproxy.command.server`

## 构建

### javac 编译报「找不到符号 getXxx()」

Lombok 注解处理器未启用。用 `-proc:full`（不要用 `-proc:none`）。

## 通用排查顺序

1. 看 `[INFO]/[WARN]/[ERROR]` 日志定位 handler（InitialHandler / ServerConnector / UpstreamBridge / DownstreamBridge）。
2. 协议类问题先对照 `Bungee/` 参考源码与 Minecraft 官方 wiki 的包 ID。
3. 数据库问题先查 `SystemConfig` 表与实体 schema 是否一致。
4. 代理链路问题按「登录 → 切换 → 补全 → TabList → 皮肤 → 插件消息」逐段验证。
